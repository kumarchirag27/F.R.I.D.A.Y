🏗️ Architecture Overview

F.R.I.D.A.Y. is a voice-controlled AI assistant specialized for cybersecurity reconnaissance. It combines modern web technologies with powerful OSINT tools to create an Iron Man JARVIS-style interface for authorized security testing.

  • Voice-controlled interface with JARVIS-like personality

  • Real-time reconnaissance with streaming results
  • Multi-platform support (Windows, Mac, Linux)

🐍 Phase 2: Backend (Claude Code)

Step 3 — FastAPI Server

Create a FastAPI server in Python with WebSocket support, CORS enabled, and a REST endpoint `/api/friday` that accepts a JSON body with fields: `query` (string), `target` (string, optional), `mode` (string). Also create a WebSocket endpoint at `/ws` for real-time streaming responses.

Step 4 — LLM Brain (brain.py)

Create a `brain.py` file that connects to the Groq API using the groq Python SDK. Use model `llama-3.3-70b-versatile`. Give FRIDAY a system prompt that defines it as a cybersecurity recon assistant. It should parse user intent, decide which recon tool to call, call it, then summarize the results in plain English. Use Groq's tool calling / function calling feature so the LLM can trigger recon modules automatically.
System Prompt Template:
"You are F.R.I.D.A.Y., an AI-powered cybersecurity reconnaissance assistant. You only operate on targets the user explicitly provides and confirms they have authorization to test. You never assume authorization. Before any recon, confirm the target and scope. Respond like JARVIS — professional, precise, concise."

🔧 Step 5 — Reconnaissance Tool Modules

Build each tool as a standalone Python function. Tell Claude Code to create these modules:

Tool 1 — DNS Reconnaissance (dns_recon.py)

Build a DNS recon tool using Python's `dnspython` library. Functions needed: `get_a_records(domain)`, `get_mx_records(domain)`, `get_ns_records(domain)`, `get_txt_records(domain)`, `get_cname_records(domain)`. Return results as structured JSON.

Tool 2 — WHOIS Lookup (whois_tool.py)

Build a WHOIS lookup tool using the `python-whois` library. Extract: registrar, creation date, expiry date, registrant org, name servers, and registrant country. Return as clean JSON.

Tool 3 — IP Intelligence (ip_recon.py)

Build an IP intelligence tool that queries ipapi.co for geolocation (country, city, ISP, ASN), then queries the Shodan API for open ports and services on that IP. Combine results into a single JSON response.

Tool 4 — Port Scanner (port_scanner.py)

Build a port scanner using Python's `socket` library for basic scanning and `python-nmap` for service detection. Inputs: `target_ip` (string), `port_range` (string, default '1-1000'), `scan_type` (string: 'basic' or 'service'). Return open ports with service names and versions as JSON. Add a hard warning comment that this should only run against authorized targets.

Tool 5 — Subdomain Enumeration (subdomain_enum.py)

Build a subdomain enumeration tool. Use two methods: 1) DNS brute force using a wordlist of top 100 common subdomains, 2) Query SecurityTrails API for historical subdomains. Combine and deduplicate results. Return as JSON list with status (alive/dead) for each.

Tool 6 — HTTP Header Analysis (header_analyzer.py)

Build an HTTP header analyzer using Python `requests`. Fetch headers from a given URL and analyze for: missing security headers (CSP, HSTS, X-Frame-Options, X-Content-Type), server technology leakage, cookie security flags, and HTTPS enforcement. Return findings with severity ratings (HIGH/MEDIUM/LOW/INFO).

Tool 7 — OSINT Aggregator (osint_aggregator.py)

Build an OSINT aggregator that takes a domain or IP and runs: VirusTotal reputation check, check if domain/IP appears in threat intelligence feeds via VirusTotal, and Have I Been Pwned breach check for associated emails found in WHOIS. Combine all into a risk summary JSON.

🔀 Step 6 — Tool Router

Create a `tool_router.py` that maps LLM tool call names to actual Python functions. When the LLM returns a tool call like `{tool: 'dns_recon', params: {domain: 'example.com'}}`, this router should execute the right function, handle errors gracefully, and return results back to the LLM for summarization.

🎤 Step 7 — Voice Layer (Optional)

Create `stt.py` using the `faster-whisper` library for local speech to text — no API needed, runs on device. Create `tts.py` using `edge-tts` with voice `en-US-RyanMultilingualNeural`. Both should stream — STT streams recognized words in real time, TTS streams audio chunks as they're generated.

🎨 Phase 3: Frontend (Lovable.dev)

Step 8 — Lovable.dev UI Prompts

Open Lovable.dev and use these prompts in sequence:

Prompt 1 — Base Layout

Create a full-screen dark futuristic AI assistant UI called FRIDAY. The background should be a deep space / dark tech aesthetic with subtle animated grid lines. Use a color palette of deep black (#0a0a0f), electric blue (#00d4ff), and soft white (#e8f4f8). No rounded corners on main containers — use sharp angular cuts for a military HUD feel. Use the font 'Rajdhani' or 'Orbitron' from Google Fonts.

Prompt 2 — Navigation Bar

Add a top navbar with sharp angled edges (not rounded). Left side: FRIDAY logo text with a small animated pulse dot. Center: navigation links — Dashboard, Recon, Intel, Settings. Right side: system status indicators showing API status, mic status, and a digital clock. Use liquid glass / frosted glass effect with electric blue border.

Prompt 3 — Central Blob Animation

Add a central animated blob component that reacts to microphone input. When idle: slow breathing pulse in electric blue. When listening: faster pulse, color shifts to cyan. When processing: rotating animation, color shifts to amber. When responding: wave animation, color shifts to green. The blob should sit center screen.

Prompt 4 — Reconnaissance Panel

Add a recon input panel below the blob. It should have: a text input field with label 'TARGET', a dropdown for scan type (DNS Recon, IP Intel, Port Scan, Subdomain Enum, Header Analysis, Full OSINT), an authorization checkbox that says 'I confirm I am authorized to scan this target', and a sharp angular EXECUTE button in electric blue. All elements should have the same futuristic HUD styling.

Prompt 5 — Results Terminal

Add a terminal-style results panel on the right side of the screen. It should look like a real terminal with: a top bar showing 'FRIDAY TERMINAL v1.0', monospace font (JetBrains Mono), green text on near-black background, typing animation when new results arrive, auto-scroll to latest output, and a copy button. Results should stream in line by line.

Prompt 6 — Status Widgets

Add four draggable status widgets positioned around the screen. Each widget uses the same sharp angular HUD style. Widget 1: System Status (FRIDAY Online/Offline). Widget 2: Current Scan Progress (progress bar + percentage). Widget 3: Threat Level Indicator (LOW/MEDIUM/HIGH/CRITICAL with color coding). Widget 4: Scan History (last 5 scans as clickable list). All widgets should be right-clickable with Move and Save Position options.

Prompt 7 — Intelligence Report View

Add a slide-in panel from the right that shows a formatted intelligence report. It should have sections for: Executive Summary, DNS Records table, Open Ports table, OSINT Findings (with severity badges), Security Headers Analysis (color coded), and a Risk Score gauge (0-100). Add an Export as PDF button and a Copy Raw JSON button.

Prompt 8 — Voice Interface

Add a microphone button that toggles voice input mode. When active, show a waveform visualizer around the blob. Add a speech transcript display below the blob showing what FRIDAY heard. Add a FRIDAY response display showing what FRIDAY is saying with a typing cursor animation.

🔗 Step 9 — Connect Frontend to Backend

After Lovable generates the UI, export the code and tell Claude Code:

Connect this React frontend to our FastAPI backend. Replace all placeholder functions with real API calls. The recon panel EXECUTE button should POST to `/api/friday` with the target and scan type. Results should stream in via WebSocket at `/ws`. The voice input should send audio to `/api/stt` and play back TTS from `/api/tts`. Handle loading states, errors, and connection drops gracefully.

🛡️ Phase 4: Safety & Ethics Layer

This section is NON-NEGOTIABLE and must be implemented exactly as specified.

🚨 Step 10 — Authorization Gate (Mandatory)

Add a mandatory authorization check before any scan runs. The user must: 1) Check a checkbox confirming authorization, 2) Type the target domain/IP manually (no paste from clipboard auto-fill), 3) A backend middleware should reject any scan request that doesn't include a confirmed authorization flag. Log all scan requests with timestamp, target, scan type, and user confirmation status to a local audit log file.

🎯 Step 11 — Scope Limiting

Add a scope configuration in settings. Users can define an allowed target list (their own domains/IPs). If a scan target doesn't match the allowed list, FRIDAY should warn: 'This target is not in your authorized scope. Please confirm you have written authorization before proceeding.' Add a bypass confirmation dialog that requires typing 'I CONFIRM' manually.
